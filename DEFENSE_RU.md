# IAIDev: подготовка к защите

Пять HTML-страниц, один CSS-файл, обычный JavaScript и jQuery. Серверная часть и сборка не нужны. Найдите каждую функцию в коде и повторите демонстрацию своими руками.

## Что сказать о проекте

«IAIDev - учебный сайт магазина компьютерной техники. Мы продолжили Midterm и Endterm: сохранили каталог, сравнение, формы и галерею. В Final добавили тему, локальный вход, FAQ и публичный API. Используем HTML, CSS, JavaScript и jQuery. Для доработки и проверок использовался ChatGPT / Codex, это указано на сайте и в отчёте».

Это учебный вход в браузере. Он не проверяет личность на сервере. Сайт не принимает заказы и оплату.

## Частые вопросы и короткие ответы

**DOM?** HTML-страница в виде дерева объектов. JavaScript находит элементы, меняет текст, классы и атрибуты.

**DOMContentLoaded?** Событие после построения HTML. Теперь можно находить формы и кнопки и назначать им события.

**localStorage?** Хранилище строк в браузере для одного origin: протокол + домен + порт. Данные остаются после перезагрузки. Это не серверная база.

**Как сохранить объект?** `JSON.stringify(user)` делает строку. `JSON.parse()` восстанавливает объект. Ошибку неверного JSON перехватывает `catch`.

**Какие ключи используются?** `iaidev-theme` - тема; `iaidev-user` - имя/email; `iaidev-products` - личный список.

**Почему при выходе не clear()?** `localStorage.clear()` удалит также тему и товары. `removeItem('iaidev-user')` удаляет только профиль.

**Где пароль?** Для задания достаточно статуса входа или несекретных данных. В Final пароль не требуется. Поля паролей из Endterm только показывают валидацию и ничего не сохраняют.

**Как работает тема?** Меняется `data-bs-theme` у `html`. Bootstrap меняет стандартные элементы, наши CSS-переменные меняют цвета сайта. На каждой странице читается сохранённое значение.

**preventDefault()?** Отменяет обычную отправку формы, чтобы она не перезагрузила страницу до нашей проверки.

**Как проверяется email?** Базовое регулярное выражение и браузерная проверка `type="email"`. Это проверка формата, а не существования почтового ящика.

**JavaScript и jQuery?** JavaScript - язык, jQuery - библиотека на нём. `$()` выбирает элементы, `.on()` назначает обработчик события.

**Как работает FAQ?** `aria-controls` содержит ID ответа. По клику вызывается `slideToggle(200)`, меняются `aria-expanded` и значок. `stop(true, true)` убирает очередь анимаций при быстрых кликах.

**API?** Интерфейс другого сервиса, через который получаем данные. DummyJSON предоставляет учебные ноутбуки и смартфоны. HTTP-запрос настоящий, данные демонстрационные.

**fetch и JSON?** `fetch()` отправляет запрос и возвращает Promise с ответом. `await response.json()` читает JSON как JavaScript-объект.

**async/await?** Удобная запись работы с Promise. `await` ждёт результат внутри функции, при этом остальной интерфейс остаётся доступным.

**Зачем response.ok?** HTTP 404 или 500 сами по себе обычно не вызывают ошибку `fetch()`. Мы проверяем статус и делаем `throw new Error()`.

**try/catch/finally?** `try` - запрос; `catch` - сообщение об ошибке; `finally` - включить кнопки обратно при любом результате.

**AbortController?** Отменяет запрос, если он не завершился за 10 секунд. Так загрузка не продолжается бесконечно.

**Как создаётся карточка?** Клонируем HTML из `template`, заполняем заголовок, бренд, цену, фото и добавляем в контейнер.

**Почему textContent?** Имя пользователя и текст из API должны показываться как текст. Через `innerHTML` посторонний HTML мог бы попасть в страницу.

**Почему USD?** Основной каталог использует примерные цены в тенге, внешний API - учебные цены в USD. Валюта указана явно, пересчёта нет.

**Если нет интернета?** Локальные страницы, тема, профиль, FAQ и фотографии работают. Онлайн-подборка покажет ошибку. После восстановления сети можно нажать «Обновить».

**Адаптивность?** Flexbox организует меню, Grid - карточки, медиазапросы меняют макет под ширину устройства.

**CRUD?** Create, Read, Update, Delete: добавить, показать, изменить, удалить. Список хранится в массиве и localStorage; таблица обновляется после изменения.

## Перед защитой

1. Проверьте опубликованный сайт и доступ к DummyJSON на сети аудитории.
2. Для демонстрации используйте `Demo Student` и `student@example.com`.
3. В DevTools → Application → Local Storage покажите ключи. В Network найдите запрос DummyJSON и его JSON-ответ.
4. Откройте `final.js`, `theme.js`, `style.css`; не начинайте разбирать минифицированные библиотеки в `vendor`.
5. Локальный резерв: `python -m http.server 8000 --bind 127.0.0.1`, затем `http://localhost:8000`.
6. Каждый отдельно сдаёт обе ссылки в LMS до 18.11.2026. Точное время смотрите в LMS. Не делайте коммиты сдаваемой версии после дедлайна.

Пройдите весь сценарий каждым участником. Отчёт и шпаргалка помогают подготовиться, но вопросы на защите требуют собственного понимания.
